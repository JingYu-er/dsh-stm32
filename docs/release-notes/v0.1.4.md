# v0.1.4 —— 21 族 HAL、13 族寄存器、真实探针与内置资源

> 继 v0.1.3（2026-10-31）之后的第二个正式版本。0.1.3 把 F1 全系、RTT、SVD 和结构化探针错误做成了可用底座；0.1.4 把这套底座扩到多族，并把「资源仓库、探针型号、烧录后端」这些外部假设逐个拆掉。
>
> 一句话：**从「F1 + 独立资源仓 + 只认 CMSIS-DAP」变成「21 族 HAL / 13 族寄存器 + 资源随包 + ST-Link / DAPLink / J-Link 都能烧」**。

## 0.1.3 → 0.1.4 一览

| --- | --- | --- |

| 设备资源 | 独立仓 `dsh-stm32-assets`，首次下载 core 约 237 KiB | 随插件内置，105 个 manifest 文件 / 12.48 MB 源文件，离线可用 |

| tarball | 约 525.7 KB | 1750.3 KB（资产随包） |

## 亮点

- **HAL 建工程扩到 21 个单核族**：C0 / F0 / F1 / F2 / F3 / F4 / F7 / G0 / G4 / H5 / H7 / L0 / L1 / L4 / L4+ / L5 / U0 / U3 / U5 / WBA / WL。双核 WB 仍只保留画像，尚未接入建工程。
- **寄存器建工程扩到 13 族**：C0 / F0 / F1 / F2 / F3 / F4 / F7 / G0 / G4 / L0 / L1 / L4 / U0。芯片事实全部来自内置 `assets/device/<族>/chips.json`，不再手抄启动文件、设备宏、Flash/RAM。
- **CubeMX db 驱动的 .ioc 事务**：新增 R13–R21 规则与 49 条 schema 闸门；`stm32_ioc_verify` 让 CubeMX 自己回写一份「它认了什么」，再和计划逐键对比。USART/UART/LPUART、TIM 时基、ADC 多 Rank、DMA 通道都有预设；时钟规划覆盖 18 族，PLL1 四族（H5 / U5 / WBA / L4+）可用。
- **设备事实自动化**：资源生成阶段，SVD 走「本地 → 缓存 → 联网」四级来源，RM 走 sitemap 主源 + stmcu 备案双通道；`extractRmFacts` 用锚点 page±3 逐字回查 + SVD 位域交叉，把「人核」换成两道机检。芯片级 spec 门禁只拦踩过坑的族，不搞一刀切。
- **烧录不再假设 CMSIS-DAP**：按 USB 实见探针选 interface——ST-Link → `interface/stlink-dap.cfg`，DAPLink/CMSIS-DAP → `interface/cmsis-dap.cfg`，J-Link → `interface/jlink.cfg` 并补 `transport select swd`。`probeError` 扩到 9 类，新增 `probe-interface-mismatch`；openocd 认不出时 `stm32_flash` 可自动改走 STM32CubeProgrammer CLI。
- **调试快路径**：`stm32_debug_eval` 优先走常驻 GDB MI 会话；新增 `stm32_watch`（变量采样 + 硬件观察点）与 si/ni 单指令步进；`stm32_regs_read` 走 openocd Tcl RPC，仍是毫秒级。RTT 修掉 0.1.3 里「outputSchema 必失败」的宿主校验问题，并补齐环形缓冲回绕、帧对齐、会话重起与 stop 释放。
- **资源随插件内置**：`dsh-stm32-assets` 全部并入本仓 `assets/`，129 个文件、12.48 MB；manifest 105 个文件（core 75 / full 105），逐文件 sha256。删除整套下载器；`stm32_assets` 只做 list / verify / prune，`refresh` 保留为 verify 的旧名。资源不再联网下载，离线可用。
- **安装与诊断闭环**：`stm32_env_probe` 并入 `stm32_doctor`（能力矩阵 / 建议 / 搜索范围）；HAL 固件包支持 ST 官网直取 + CRC 校验 + `swmgr` 记账，失败回退 GitHub 拼包；缺 CubeMX / CubeProgrammer 时直接给下载入口，不再只报「命令找不到」。

| --- | --- |
| `stm32_ioc_verify` | **新增**。把 .ioc 复制到临时目录，让 CubeMX 无头 load/save，回写它理解的结果；报告 droppedPeripherals / signalRewrites / plannedFunctions / attribution。 |
| `stm32_watch` | **新增**。value 采样 + write/read/access 硬件观察点；与断点共用 F1 的 4 个数据比较器预算。 |

| `stm32_flash` | 新增 `backend: auto \| openocd \| cubeprogrammer`；默认 auto 先 openocd，失败再试 CubeProgrammer；工程自带 `openocd.cfg` 优先。 |

| `stm32_rtt` | 修复 0.1.3 的 outputSchema 包裹错误；follow/dump 自动起通道、死会话重起；stop 一并释放自己起的调试会话。 |
| `stm32_project_create` | 寄存器路线建完自动补 `.vscode/` 三份配置（HAL 路线原本就走 scaffold 模板）；launch.json 的 interface 按实见探针替换。 |
| `stm32_doctor` | 合并 env_probe；新增工具链能力矩阵、安装建议、搜索范围、USB 探针识别与 .ioc 告警。 |
| `stm32_firmware_install` | 官网直取通道：FwLibrary 拼 URL + Content-Length/CRC32 校验 + swmgr 安装；许可缺失时明确说缺哪个标签并回退 GitHub 拼包。 |

## 破坏性变更

| 变更 | 影响 | 迁移 |
| --- | --- | --- |
| `stm32_env_probe` 被移除 | 直接调用该工具的脚本/提示词会找不到工具 | 改用 `stm32_doctor`；能力矩阵与安装建议在返回的 report 里 |
| `stm32_assets refresh` 不再下载 | 指望 refresh 拉新资源的自动化会「成功但什么都没更新」 | 资源已随包；怀疑装坏就跑 `stm32_assets verify`，缺文件就重装插件。`DSH_STM32_ASSETS` 仅保留为开发覆盖 |
| 寄存器工程模板文件数 9 → 12 | 断言 `templateFiles` 的脚本会失败 | 新工程多了 `.vscode/c_cpp_properties.json`、`.vscode/launch.json`、`.vscode/settings.json`；已存在的文件不覆盖 |
| `stm32_flash` 默认后端改为 auto | 只装了 CubeProgrammer、没装 openocd 的机器行为会变；日志里可能出现第二后端 | 需要固定行为就显式传 `backend: "openocd"` 或 `backend: "cubeprogrammer"` |
| 工程自带 `openocd.cfg` 优先 | 插件不再强行按实见探针改写工程里的 interface | 想用插件自动选 interface，就移除/改名工程里的 `openocd.cfg` |

## 修复

- **RTT 在 0.1.3 里必失败**：`stm32_rtt` 的 outputSchema 少包了一层 message/report，宿主校验直接拒绝；本版修正，并补 follow 流式读、固件侧 `s_dropped`、环缓冲写偏移回绕、尾部半帧不判失败、帧边界对齐。
- **探针错误漏判**：分类改用完整日志；补 `target-mismatch`、`probe-busy`（探针卡死）、`probe-interface-mismatch` 真机样本；不再把「驱动不匹配」误报成「没插探针」。
- **CI 隐藏状态**：删掉模块级探针缓存；重试方向由本次实见探针决定，避免 CI 与本地结果分叉。
- **CMake 源清单停在脚手架快照**：`stm32_generate` 后按磁盘上的 startup / 设备宏 / hal_conf 重算，补上 CubeMX 拆出来的 `gpio.c` 等文件。
- **CubeMX 单实例弹模态框**：生成/诊断前探测 GUI 占用；单实例会把 `-q` 转发过去并弹窗，现在直接给可执行提示。
- **寄存器模板 `delay_ms` 掐掉调用方 SysTick**：改为不占用调用方时基。
- **.ioc 写入细节**：键序纯字典序、值前导空格转义、ADC 分频同步 `ADCFreqValue`、GPIO 只写非默认属性、DMA 补齐三件套与通道中断、纯 LF 源告警。
- **固件包下载超时**：默认 30 s → 240 s（F7/L4 的 device.tgz 三源实测会超 30 s）。

## 安装 / 升级

```powershell
# npm 发布后
dsh plugin --profile desktop add dsh-stm32

# 从 git 安装（npm 未发布时）
dsh plugin --profile desktop add github:JingYu-er/dsh-stm32#v0.1.4
```

升级后重启 DSH 宿主。资源随包分发，建工程**不再联网下载**。0.1.3 的 `~/.dsh-stm32/assets/<version>` 默认不再参与查找；要读旧缓存就把 `DSH_STM32_ASSETS` 指到该目录（这样 `stm32_assets prune` 才有历史版本可清），不用了直接删除即可——内置 `assets/` 永远不会被删。

## 已知限制

- 只做 Windows（工具链依赖 MSYS2 的 gcc/cmake/ninja 与 openocd）。
- HAL 建工程覆盖 21 个单核族；双核 WB 尚未接入，MP1 / MP2 / N6 / WB0 / WL3 不在 HAL 建工程范围。寄存器建工程 13 族。
- H5 / WBA / WB0 / WL3 没有可用的 openocd target 脚本，烧录只能走 STM32CubeProgrammer（`backend: "cubeprogrammer"`）。
- SVD 符号名/位域仍只有 F1 六条 line；其他族可用寄存器地址与外设 dump，但没有 SVD 名称解释。
- RTT 只有通道 0、无 defmt 解码；启用后固件 RAM 从 1576 B 涨到 5232 B（3 个 1 KiB 环 + 控制块），且固件要先调用 `rtt_init()`。
- 真机覆盖没有随族数线性增长：HAL 21 族里只有部分族做过板级验收，其余以建工程/生成/编译为主。
- 主机侧 UART/USB CDC 串口监控仍未内置；本版观测手段是 RTT、寄存器读取与调试会话。
