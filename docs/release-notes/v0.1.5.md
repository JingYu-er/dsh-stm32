# v0.1.5 —— 串口 P1、寄存器 21 族、安装包下载与供应链加固

> 继 v0.1.4（2026-11-09）之后的下一个版本。0.1.4 把 HAL 建工程扩到 21 族、寄存器到 13 族，并把资源、探针与烧录后端的外部假设拆掉；0.1.5 把三条开发线一起收口：**Windows 串口闭环（P1）**、**寄存器建工程扩到 21 族**、**安装包只下载不安装 + P0/P1/P2 供应链/可靠性加固**。
>
> 一句话：**模型现在能自己开串口收发、给 21 族建寄存器工程、下载并校验安装包；大包校验不再吃满内存，固件安装失败也不会留下半截包。**

## 亮点

- **串口 P1（`stm32_serial`）**：七个动作 `list / open / read / send / transact / status / close`；默认 115200 8N1、DTR/RTS 不拉高、`persist=false`、单会话；`read` 支持 `cursor` 增量读、`transact` 支持正则等回包。桥是 Windows 自带的 PowerShell 5.1 + `System.IO.Ports`（插件仍然零 npm 依赖），Node 侧通过目录文件 IPC 与桥对话，桥每 5 s 查父进程、DSH 退出时自动放口。**P1 不含右侧面板 / SSE / Linux / macOS / 自动重连**。
- **寄存器建工程 13 → 21 族**：新增 H5 / H7 / L4+ / L5 / U3 / U5 / WBA / WL；8 族 `create→build` 矩阵已跑完，8/8 通过（warning 0 / error 0）。芯片事实（启动文件、设备宏、Flash/RAM）全部来自内置 `assets/device/<族>/chips.json`；GPIO 使能位按族分四种口径（含 H7 的 AHB4ENR 与 U3/U5 的 AHB2ENR1）。
- **只下载，不安装（`stm32_download`）**：`plan`（默认，只出计划）、`direct`（J-Link 真下载）、`manual`（打开 ST 官方页）、`file`（只校验本地安装包）四种模式；`dryRun` 默认 `true`，真下载/开页面必须再给 `confirm: true`。J-Link 固定 8.18.0 直链与 SHA256，边写边算哈希，校验通过才原子改名；ST 的 CubeMX / CubeProgrammer 需要 myST 登录与许可，只给官方页，不伪造直链。插件**绝不执行安装器、不写注册表、不改 PATH、不请求管理员**。
- **供应链完整性（P0）**：MSYS2 安装包固定到 2026-09-27 版本并校验 SHA256（43,117,824 B）；固件归档只走 codeload，34 个归档与 86 个内核头全部钉哈希；自定义镜像必须同时给 `MSYS2_INSTALLER_SHA256`，否则拒绝回退默认源。
- **大包不再整包读内存（P1）**：官方固件 zip 校验改为 fd 定位读取 EOCD、中央目录、逐条压缩数据，单条解压上限 256 MiB；tar 解压阶段就限流，新增流式 `extractTarGzFile`，压缩炸弹在解压时中止。
- **固件安装可回滚（P1）**：先解到 `.dsh-download-<pid>-<ts>/package`，`verifyFirmwarePackage` 通过后才把旧目录换出、staging 换入；换入后再验一次，失败自动还原。同一目录有 `.dsh-install.lock`，第二个进程会得到明确拒绝而不是互相覆盖。
- **doctor 说清「能烧不能调」（P2）**：只有 CubeProgrammer 时明确写仅 ST-LINK、不能调试；OpenOCD 缺这颗芯片的 target 脚本会报 blocker/note；J-Link 驱动缺失单独提示。gdb/openocd 不再一律 required，自动发现补上 gdb-only / ninja-only 目录。
- **系统命令不再裸调用（P1）**：`cmd.exe` / `reg.exe` / `curl.exe` 固定走 `%SystemRoot%/System32` 绝对路径；写用户 PATH 成功后同步当前进程，不用重启 dsh 才能找到新装的工具。

## 修复

- 串口 P1 在 t14 的六处收口：`abandonBridge`（失败 open 不残留占口的桥）、`openChain`（并发 open 串行化）、会话视图补 `timeoutMs/maxLines/maxBytes/idleTimeoutMs`、`transact` 的 `truncated` 与 `timedOut` 解耦、`bridge.ps1` 的 `rtscts` → `Handshake::RequestToSend`、`readSerial` 缺省用会话参数。
- 寄存器事实层：补 H7/U5 的 `linkerRam` 并同步 `assets/manifest.json`（bytes + sha256）；GPIO 使能位新增 `moder-ahb4`（H7）与 `moder-ahb2enr1`（U3/U5）。
- 寄存器模板：`-mcpu` 改为按族生成（`coreFlagOf()`；H7=cortex-m7，M33 五族=cortex-m33，L4+/WL=cortex-m4），H7 下载清单补 `cachel1_armv7.h`（`extraCoreHeaders`，模板 10→11 个文件）。
- 下载文案：没有官方哈希时明确写 `verified:false`，不再假报「校验完成」。
- `openOfficialPage` 等 `cmd` 退出码，起不来/超时返回 `false`，不再假报「页面已打开」。

## 安装 / 升级

```powershell
dsh plugin --profile desktop add dsh-stm32@0.1.5
# 或从 GitHub 主线：dsh plugin --profile desktop add github:JingYu-er/dsh-stm32#main
```

- 安装/升级后需**重启 dsh** 才加载新代码。
- 资源随包内置，不需要联网刷新；怀疑装坏就跑 `stm32_assets verify`，缺文件重装插件。
- 串口 P1 只在 Windows 可用；Linux / macOS 会返回 `unsupported-platform`。

## 已知限制

- **串口 P1 只在 Windows**：桥是 PowerShell 5.1；不含 UI 面板、SSE、自动重连，一次只开一个口。
- **串口成功路径未上真机**：`state=open`、真实收数、DTR/RTS 实际电平、5 s 看门狗、idle 自动放口、`port-busy` / `access-denied` 都没有硬件样本（假桥覆盖同一契约）。
- **C031F6P6 没有完整闭环证据**：C0 的 OpenOCD target 脚本是上游 master 的 0.12 适配版，语法加载已验；能连上、能烧、烧完能跑、能 halt/step 还没在真板上跑过。
- **CubeProgrammer 探测仍按文件存在判定**：不启动 JVM，避免 doctor 多等数秒；真正烧录失败会在 flash 阶段报错。
- **SVD 覆盖仍以 F1 为主**：寄存器符号名与位域解释只在 `assets/device/f1/svd` 上验证；新增族按地址读可用，按符号名读待补。
- 其余限制沿用 0.1.4（Windows 宿主、CubeMX 依赖、探针默认 CMSIS-DAP 等）。
