# v0.1.5 —— 串口 P1 与寄存器 21 族

> 继 v0.1.4（2026-11-09）之后的下一个版本。0.1.4 把 HAL 建工程扩到 21 族、寄存器到 13 族，并把资源、探针与烧录后端的外部假设拆掉；0.1.5 补上 **Windows 上的串口闭环（P1）**，并把**寄存器建工程扩到 21 族**。
>
> 一句话：**从「寄存器 13 族、串口只能靠人肉串口助手」变成「寄存器 21 族、模型自己开串口收发」**。

## 0.1.4 → 0.1.5 一览

| 维度 | 0.1.4 | 0.1.5 |

| 寄存器建工程 | 13 族 | 21 族（+ H5 / H7 / L4+ / L5 / U3 / U5 / WBA / WL） |
| HAL 建工程 | 21 个单核族 | 21 个单核族（不变） |
| 时钟规划 | 18 族 | 18 族（不变） |

> 数字口径：表中数字为 0.1.5 开发树实测（`run-units` / `test:size` / `test:pack`），最终验收复核；不要手抄中间过程的数字。

## 亮点

- **串口 P1（`stm32_serial`）**：七个动作 `list / open / read / send / transact / status / close`；默认 115200 8N1、DTR/RTS 不拉高、`persist=false`、单会话；`read` 支持 `cursor` 增量读、`transact` 支持正则等回包。桥是 Windows 自带的 PowerShell 5.1 + `System.IO.Ports`（插件仍然零 npm 依赖），Node 侧通过目录文件 IPC 与桥对话，桥每 5 s 查父进程、DSH 退出时自动放口。**P1 不含右侧面板 / SSE / Linux / macOS / 自动重连**。
- **寄存器建工程 13 → 21 族**：新增 H5 / H7 / L4+ / L5 / U3 / U5 / WBA / WL；8 族 `create→build` 矩阵已跑完，8/8 通过（warning 0 / error 0）。芯片事实（启动文件、设备宏、Flash/RAM）全部来自内置 `assets/device/<族>/chips.json`；GPIO 使能位按族分四种口径（含 H7 的 AHB4ENR 与 U3/U5 的 AHB2ENR1）。
- **链接脚本按芯片给内存窗口**：H7 默认只用 DTCM 128 KiB（138 颗都带 `linkerRam`），U5 按 line 给 256 / 768 / 2496 KiB；L4+ 与 L5 是连续单块。`_estack` 落在窗口顶，RAM 溢出在链接期暴露。
- **串口 P1 的失败收口**：open 失败/超时会先 close 再 kill，留 `abandoned.json`，`status` 报 `orphanDirs`；11 类结构化错误都带中文 `cause` / `hint`。
- **文档口径统一**：README / README_EN / 阅读指南清掉「只有 F1 / 寄存器 13 族」旧文案；新增 `docs/release-notes/v0.1.5.md`（本文件）。

## 修复

- 串口 P1 在 t14 的六处收口：`abandonBridge`（失败 open 不残留占口的桥）、`openChain`（并发 open 串行化）、会话视图补 `timeoutMs/maxLines/maxBytes/idleTimeoutMs`、`transact` 的 `truncated` 与 `timedOut` 解耦、`bridge.ps1` 的 `rtscts` → `Handshake::RequestToSend`、`readSerial` 缺省用会话参数。
- 寄存器事实层：补 H7/U5 的 `linkerRam` 并同步 `assets/manifest.json`（bytes + sha256）；GPIO 使能位新增 `moder-ahb4`（H7）与 `moder-ahb2enr1`（U3/U5）。
- 寄存器模板：`-mcpu` 改为按族生成（`coreFlagOf()`；H7=cortex-m7，M33 五族=cortex-m33，L4+/WL=cortex-m4），H7 下载清单补 `cachel1_armv7.h`（`extraCoreHeaders`，模板 10→11 个文件）。
- 本轮未发现其他影响行为的修复项。

## 安装 / 升级

```powershell
dsh plugin --profile desktop add dsh-stm32@0.1.5
# 或从 GitHub 主线：dsh plugin --profile desktop add github:JingYu-er/dsh-stm32#main
```

- 安装/升级后需**重启 dsh** 才加载新代码。
- 资源随包内置，不需要联网刷新；怀疑装坏就跑 `stm32_assets verify`，缺文件重装插件。
- 串口 P1 只在 Windows 可用；Linux / macOS 会返回 `unsupported-platform`。

## 已知限制

- **串口 P1 只在 Windows**：桥是 PowerShell 5.1；不含 UI 面板、SSE、自动重连，一次只开一个口。
- **串口成功路径未上真机**：`state=open`、真实收数、DTR/RTS 实际电平、5 s 看门狗、idle 自动放口、`port-busy` / `access-denied` 都没有硬件样本（假桥覆盖同一契约）。
- **寄存器新增 8 族已过独立验收**：8 族 `create→build` 8/8 通过（warning 0 / error 0，见 development-notes §87.5），t8 独立复验也通过（21 族清单、GPIO 门、linkerRam、296 条事实断言、8 族重建全 exit 0，见 §87.6）；真机与逐颗 linkerRam 仍未验。
- **SVD 覆盖仍以 F1 为主**：寄存器符号名与位域解释只在 `assets/device/f1/svd` 上验证；新增族按地址读可用，按符号名读待补。
- 其余限制沿用 0.1.4（Windows 宿主、CubeMX 依赖、探针默认 CMSIS-DAP 等）。
