# v0.1.7 —— P1/P2 加固：流式校验、原子安装、doctor 说真话

> 继 v0.1.6（2026-11-10）之后的下一个版本。0.1.7 不新增工具，只修审计里剩下的 P1/P2：大包不再整包读内存、固件安装不再留半截包、doctor 不再用「缺 openocd」掩盖「只能烧 ST-LINK」。

## 0.1.6 → 0.1.7 一览

| 维度 | 0.1.6 | 0.1.7 |
| --- | --- | --- |
| 官方 zip 校验 | `readFileSync` 整包（WBA 388 MB） | 按偏移读 EOCD/中央目录/单条，峰值≈最大单条 |
| 固件拼包安装 | 直接解到目标目录，失败留半截 | staging + 校验 + 原子换入；失败保留旧包；跨进程锁 |
| tar 解包 | 先 `gunzipSync` 整包，再限流 | 解压阶段就限流；新增流式 `extractTarGzFile` |
| doctor 能力 | `flash` 只认 openocd | `flashOpenocd` / `flashCubeProgrammer` / `debugOpenocd` 拆开 |
| 系统程序调用 | 裸 `cmd.exe` / `reg.exe` / `curl.exe` | 固定 `%SystemRoot%/System32` 绝对路径 |
| J-Link 源 | 单条官方直链 | 官方直链；可用 URL+SHA256 成对覆盖内网镜像 |
| 下载文案 | 无哈希也写「校验完成」 | 明确 `verified:false`（无官方哈希可对比） |
| 测试 | 937 pass / 59 套件 | **947 pass / 60 套件** |
| 包体 | 1809.8 KB / 271 文件 | 1825.2 KB / 272 文件，解包 15181.3 KB |
| 破坏性变更 | — | 无（工具参数不变） |

> 数字为 0.1.7 开发树实测（`run-units` / `test:pack` / `test:size`）。

## 亮点

- **大包校验不再吃满内存**：`verifyZipCrc` 用 fd 定位读取，EOCD、中央目录、每条压缩数据分别读；单条解压上限 256 MB。WBA 的 388 MB 官方包也能在低内存机器上校验。
- **固件安装可回滚**：先解到 `.dsh-download-<pid>-<ts>/package`，`verifyFirmwarePackage` 通过后才把旧目录换出、staging 换入；换入后再验一次，失败自动还原。同一目录有 `.dsh-install.lock`，第二个进程会得到明确拒绝而不是互相覆盖。
- **压缩炸弹在解压阶段就停**：同步与流式两条 tar 路径都带 `maxOutputLength` / 字节计数；不再先解压 512 MB 再检查。
- **doctor 说清「能烧不能调」**：只有 CubeProgrammer 时明确写仅 ST-LINK、不能调试；OpenOCD 缺这颗芯片的 target 脚本会报 blocker/note；J-Link 驱动缺失单独提示。gdb/openocd 不再一律 required。
- **自动发现补上 gdb-only / ninja-only 目录**：只装了 `gdb-multiarch` 或 `ninja` 的 MSYS2 目录也会被认出来。
- **PATH 写入后当前进程立即可见**：写用户注册表成功后同步补进 `process.env.PATH`，不用重启 dsh 才能找到新装的工具。
- **不再假报「页面已打开」**：`openOfficialPage` 等 `cmd` 退出码，起不来/超时返回 `false`。

## 工具变化

| 工具 | 0.1.7 的变化 |
| --- | --- |
| `stm32_doctor` | `capabilities` 新增 `flashOpenocd` / `flashCubeProgrammer` / `debugOpenocd`；推荐语按能力生成；target 脚本与 J-Link 驱动诊断更具体。 |
| `stm32_download` | 无哈希时文案改为 `verified:false`；J-Link 支持 `DSH_STM32_JLINK_URL` + `DSH_STM32_JLINK_SHA256` 成对覆盖；打开官方页改为真实等待退出码。 |
| `stm32_firmware_install` | 安装改为 staging + 原子换入 + 跨进程锁；官方 zip 校验改流式；失败不再污染旧包。 |
| `stm32_env_install` | 写用户 PATH 成功后同步当前进程；`cmd.exe` / `reg.exe` / `curl.exe` 用 System32 绝对路径。 |
| 其他工具 | 参数与行为不变。 |

## 不做什么（边界）

- 不自动安装 J-Link / CubeMX / CubeProgrammer；仍然只下载或打开官方页。
- 不提供未经哈希校验的镜像；J-Link 覆盖源缺 SHA256 时回官方源，不静默使用。
- 不保证 OpenOCD 支持所有芯片：缺 target 脚本时明确报出来，换 J-Link 也不会自动修好 target。
- 不改用户已有固件包的内容；原子换入只发生在插件自己的目标目录。

## 安装 / 升级

```powershell
dsh plugin --profile desktop add dsh-stm32@0.1.7
# 或从 GitHub 主线：dsh plugin --profile desktop add github:JingYu-er/dsh-stm32#main
```

装完确认：`dsh plugin --profile desktop why dsh-stm32` 应显示 `0.1.7`；重启 dsh 后才加载新代码。

## 已知限制

- 官方 zip 的流式校验仍是同步 API；超大包会阻塞事件循环，但内存峰值已降到单条。
- `cmd /c start` 退出 0 不能 100% 证明浏览器真的打开了页面；失败时会提示手动复制 URL。
- J-Link 版本与哈希仍写死在 `JLINK_DOWNLOAD`；SEGGER 发新版后要同时改 URL 与 SHA256。
