# v0.1.8 —— 调试台：把「AI 做了什么、板子上发生了什么」放到同一页

> 继 v0.1.7（2026-11-12）之后的下一个版本。0.1.8 只有一个主题：**主窗口里多一个「调试台」面板**（`conversation.view`，id `stm32-debug`）。
> 25 个工具的参数与行为不变，破坏性变更为零；面板本身不新增工具，只是把既有工具的调用、结果与硬件状态按同一条时间线摆出来。

## 亮点

- **一条时间线，人机同看**：`stm32_*` 每次调用的 start / ok / fail、耗时、参数、结果摘要都在面板里，慢调用（>5 s）标黄；失败可一键筛出并跳到详情。
- **实时通道三合一**：串口（COM）、RTT、监视采样在同一页，可按关键字过滤、暂停、导出；串口可发命令，RTT 可按级别过滤。
- **证据自动落盘**：每 30 秒把未落盘事件写成 JSONL，默认保留 7 天 / 20 个会话，超限自动清理并显示占用；打开面板即载入本会话最近一份证据，可回放。
- **失败不只是一行红字**：故障页按规则解码（`build.cmake-failed`、`build.no-build-dir`、烧录/调试/串口/环境各有规则），同一规则的失败自动合并成组，可导出 CSV；编译错误与警告能直接跳到源码行。
- **工程不再靠猜**：工程根写 `dsh-stm32.conf`（name / mcu / ioc / build），工作区根记 `project=` 列表，面板顶部下拉切换工程并记住选择；没选工程时明确报「projectDir 不能为空」，不再回落到进程目录。
- **`.ioc` 有基线可对账**：写入前自动记基线，变更页列出新增 / 删除 / 改动，可恢复单个键，也可一次全部恢复（写前备份到 `<工程>/.dsh-stm32/backups`）。
- **时钟超限给的是能配的档**：建议按「分频器挂在谁身上」算（ADC 除 PCLK2、APB 除 HCLK），并区分「工程没启用 ADC」这种不算错的派生值。
- **视觉跟随宿主**：瑞士国际主义版式（直角、发丝线、等宽大写小标、单一强调色），颜色全部走宿主设计令牌 —— 宿主深色即深色、浅色即浅色，强调色随主题取 `state-business-primary`。

## 面板的十个标签

| 标签 | 看什么 | 能做什么 |
| --- | --- | --- |
| 概览 | 工程、型号、SYSCLK、容量、调试会话、工具链、构建/烧录、证据占用、告警一句 | 跳到失败筛选、实时通道，导出操作记录 Markdown |
| 事件 | start/ok/fail、耗时、慢调用标黄、入参摘要 | 只看失败、按工具名筛选、按耗时排序、批量勾选复制引用、导出 JSONL、深链 `#stm32-debug:event=<seq>` |
| 实时通道 | 串口 / RTT / 监视三路输出 | 暂停、清空、关键字过滤、RTT 级别过滤、发送串口行、常驻采集、导出文本 |
| 引脚 | 按外设分组、按端口排布、按封装方框（LQFP 方框取自 CubeMX `db/mcu/<型号>.xml` 的 `Position`） | 筛选、复制引脚引用、看该脚在 `.ioc` 的键、导出 CSV（BOM + CRLF） |
| 时钟 | 树与流向两种视图、各节点频率与分频 | 看超限标记与「改成 ÷N」建议（按父时钟算） |
| 中断 | NVIC 使能、抢占/子优先级 | 筛选、排序、就地改优先级、勾选批量改（一次备份一次写盘） |
| 故障 | 失败事件原文 + 规则解码 + 按规则合并 | 分类/规则筛选、复制组提示、导出 CSV |
| 产物 | elf/hex/bin、大小、SHA-256、芯片容量、两次构建对比 | 复制校验和 |
| 变更 | 当前 `.ioc` 与基线的差异 | 记基线、恢复单个键、一次恢复全部 |

## 数据面

- 46 条 `/dsh-stm32/api/*` 路由；事件流用 SSE（`/events?since=<seq>&session=<id>`），先补发存量再增量，断线重连只补缺口。
- 环形缓冲 5000 条、单条 payload 截 8 KB；落盘按会话分文件，缺口会写成一条显式的缺口事件，复盘时不会把「丢了 5 条」当成「只有这些」。
- 保留策略可配：`evidencePolicy`（flush 5–3600 s、保留 0–365 天 / 1–200 会话），环境变量 `DSH_STM32_EVIDENCE_*` 优先于配置。
- 事件源只有本插件的 `stm32_*` 工具（注册期用 Proxy 包一层，不改 25 个 execute）。
- 面板与工具共用同一套引擎状态：调试会话、串口、RTT、监视、构建、烧录都不另起第二份账本。

## 修了什么

- **工程目录回落进程目录**：未选工程时曾把 `process.cwd()` 当工程（在插件仓库里会读写到插件自身）。现在统一兜底链：显式传参 → 当前调试会话的工作目录 → `~/.dsh-stm32/last-workspace.txt` 备忘 → 明确报错。
- **引脚页 / 时钟页白屏**：引脚页是 TDZ（`totalPins` 在声明前被用），时钟页是早退之后再调 `useState` 导致钩子数量变化；两处都补了渲染级测试。
- **编译摘要丢警告**：`build` 的 digest 只带错误不带警告，现在带 `warnings`（截 20 条）并可跳源码。
- **构建占用来源说不清**：增量构建时 `cmake` 不打印 size，改用 `arm-none-eabi-size` 兜底量 elf，notes 里注明数字来自 size 还是 cmake。
- **超限建议算错一级分频**：原来用「当前频率 ÷ 分频」给建议（ADC 36 MHz 给 ÷4=9 MHz，实际 ÷4 是 18 MHz 仍超限），改为按父时钟算，未启用 ADC 时标注「不影响运行」。
- **扫描噪音**：工作区扫描会把 `build/`、`node_modules/` 里带 CMakeLists 的目录当成工程，现已排除；工作区根自身就是工程时不再下扫。
- **插件自检**：`/status` 增 `self:{version, libMtimeMs, startedAt, routeCount}`，`lib` 比进程新时面板提示「有新构建」。

## 不做什么（边界）

- 不做代码编辑、不做 Git 操作；面板只展示与执行明确的工程动作。
- 不替用户改 `.ioc` 而不留痕：所有写操作先备份，且只改明确的键。
- 不把事件源扩到别的插件：调试台只认本插件的 `stm32_*` 调用。
- 不保证所有芯片的封装方框：CubeMX db 里没有 `Position` 时降级为「按端口排布」并给出提示。

## 升级方式

- 客户端（`client/client.js` 与 `lib/client.js`）：刷新页面即可看到新面板；首次使用若没看到页签，完全退出 DSH 再启动。
- 服务端（`src/**` → `lib/**`）：必须完全退出 DSH 再启动（关窗口不够）。
- 版本确认：状态条显示 `v0.1.8 · 46 路由`；`dsh plugin --profile desktop why dsh-stm32` 应显示 `0.1.8`。
- 不需要迁移：证据目录与 `dsh-stm32.conf` 都是新增文件，旧工程首次打开时自动补写。
